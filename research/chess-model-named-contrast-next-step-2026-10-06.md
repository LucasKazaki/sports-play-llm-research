# Next bounded chess implementation: compare the alternative the model actually named

**Planning handoff, 6 October 2026. No implementation, model call, engine call, or new empirical result is claimed here.** This plan is for development positions only. The no-forward capability gate in `research/chess-commentary-capability-gate-v1.md` remains open.

## Why this is the next useful increment

The v8/v9 checker already replays exact moves and squares. In v9, a queen claim can show that `17.Qc2` moves an attacked queen while a model-named `17.Rc1` leaves it exposed to the legal conditional `...Nxd1`; the rook claim can name a legal open-file alternative. Those are inspectable board facts, but v9 explicitly returns an abstaining comparison and cannot say which choice the engine scored higher. Its checking-capture and passed-pawn claims name no alternative at all (`scripts/chess_no_forward_teaching_v9.py:84-145,161-250`). The four retained 10,000-node paired searches selected their own alternative. Three have bounded scores; the one finite difference is a single search. The existing v10 *attachment design* correctly abstains for all four model-named examples because the names or score qualifications do not match. Implementing only that attachment would improve restraint but produce no positive contrast on the retained practice set.

The next implementation should therefore measure the **accepted model-named alternative**, after generation, in one source-bound root-restricted search. It must keep a checked legal mechanism separate from a finite engine score observation. A score difference cannot prove Stockfish's reason, forced play, or teaching quality.

## One software increment and its boundary

Add a separately versioned evaluator, tentatively `scripts/chess_model_named_contrast_v11.py`, and `tests/test_chess_model_named_contrast_v11.py`. Do not modify the v8/v9 prompt, nine-field generator projection, old checker verdicts, historical paired records, or `scripts/chess_arbitrary_move_contrast_v1.py`. A narrow entrypoint should accept exact packet bytes/hash, raw response bytes/hash, source binding, a pinned engine/source identity, and an injected engine. It should:

1. Rebuild the v9 nine-field projection and recompute `v9.evaluate` from the original raw response. Require `decision=verified_typed_board_claim`, an accepted `witness.alternative_uci`, and a different legal root move. Otherwise return an explicit no-comparison record **before** touching the engine. The checker must never select an alternative to rescue a model claim.
2. Revalidate the original game's source hash, ply, pre-move FEN, selected UCI, and model alternative against the retained source receipt. Freeze the pair `(selected_uci, alternative_uci)` and the pre-move mover's perspective. Reject mismatched packet, source, raw-response, checker, engine binary, or settings hashes before search.
3. With only those two roots, request one MultiPV=2 paired search at each preregistered 30,000 and 100,000 node budget. Each search uses the same pre-move board, Stockfish 19 binary, one thread and 16 MB hash. No unrestricted discovery search is needed because the model already chose the alternative. Record requested roots, budget, final depth and nodes, score type/bound/perspective, legal-PV validation, timestamps, failures and not-run stages. Keep PVs and any resulting board **evaluator-only**. Reuse the already reviewed event checks in `scripts/chess_arbitrary_move_contrast_v1.py:65-149` or implement equivalent versioned checks; do not weaken its equal-depth, minimum-node, root-identity or timeout guards.
4. Emit an exact numeric `alternative_minus_selected_cp` only when both roots have unqualified centipawn scores at both budgets, from the same mover's perspective, and the ordering and predeclared drift rule agree. A mate, bound, missing rank, unequal depth, insufficient nodes, root mismatch, engine failure or unstable order yields an explicit abstention. A separately typed **reported-search-score floor** may be allowed for the already reviewed one-sided pattern (selected upper bound, alternative unqualified at both budgets), following `chess_arbitrary_move_bound_reducer_v2.py:62-169`; never call that a bound on true position value or an exact loss.
5. Return two distinct parts: `legal_witness` copied from the rechecked v9 verdict, and `engine_observation` with source/search receipts or abstention. Set `stockfish_intent_supported=false`, `forced_line_supported=false`, `quality_evaluated=false`. Any display sentence may say that a named reply is **legal** and the alternative **scored higher in these searches**; it must not say the score proves that reply is the reason. No new free-form prose from the model is admitted.

The existing `research/chess-model-named-pair-v10-plan-2026-10-06.md` can serve as a read-only baseline for matching an already retained pair. This new increment addresses the limitation that its retained pairs do not use the model's alternatives. Keep v10's design-only status until it is actually implemented and reviewed; use a distinct schema/version for the new search record.

## Focused verification and evidence

- Start with fail-first fake-engine tests: no call for rejected, abstaining or no-alternative v9 output; no call for altered source/hash/ply/FEN/move; exact two-root arguments at both budgets; side-to-move perspective for Black; duplicate/missing root, illegal PV, stale bound, unequal depth, insufficient nodes, timeout, cleanup error, mate and unstable score. Test a valid exact-score pair and the narrowly qualified one-sided floor separately.
- Assert byte-for-byte invariance of `v9.build_generator_input` and its nine keys before and after evaluation. Negative controls must reject nested PV, future board, alternative score, Game Review text and evaluator material **before any generator call**. The engine receives the accepted raw response only after that response is frozen; nothing returns to the generator.
- Run the focused tests with `.venv-soccernet\Scripts\python.exe -m pytest -q tests/test_chess_model_named_contrast_v11.py tests/test_chess_no_forward_teaching_v8.py tests/test_chess_no_forward_teaching_v9.py tests/test_chess_arbitrary_move_contrast_v1.py tests/test_chess_arbitrary_move_bound_reducer_v2.py`. Retain fail-first and green stdout, exact source/test hashes, and a complete native `project-execution` receipt. These tests are software checks, not chess-quality measurements.
- Only after v9's formal source review passes and an actual create-only v9 model attempt yields an accepted named alternative should one **separate** create-only development engine capture be considered. Bind its PGN/packet/raw-output/engine hashes, native task/job/receipt, complete attempted/not-run denominator and offline verification. If all four outputs abstain, record 0/4 usable named contrasts; do not substitute synthetic claims or a different engine-selected move. Do not touch a fresh holdout.

Route the exact new source, meaningful tests and retained test result through `sports-play-llm-project-executor` as a complete bundle below 30,000 bytes, split into finite bundles if necessary. Select the bundle's native stdout in `input.resultTask.readCommandIndices`; use `sports-play-llm-developer`. This source review does not substitute for the independent receipt-based chess capability review or qualified teaching judgment.
