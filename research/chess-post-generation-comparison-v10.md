# V10: checking one model-named alternative after the explanation is sealed

This development sidecar is for the four known Chess.com practice positions. V9 gives the model only a source-checked, nine-field pre-move packet. After the raw response and offline v9 verdict are saved, v10 can compare the played move with an alternative that the model actually named and the v9 checker accepted. The comparison does not tell us why Stockfish prefers a move, and it is not a teaching-quality result.

## What is fixed before a model response

`freeze-protocol` writes canonical JSON with a pinned Stockfish 19 binary, one thread, 16 MB hash, one 100,000-node search, MultiPV 2, and roots `[played, accepted model alternative]`. There is no discovery search or adaptive retry. The protocol also includes the SHA-256 of this evaluator and a digest of v9's 23-module implementation closure. `compare` checks those source pins again before calling the engine. A caller must freeze and retain the protocol before the v9 model response; the v10 code checks the bytes and hashes but cannot prove their creation time on its own.

## What v10 will accept

After v9 seals a response and offline evaluation, `freeze-input` builds the input from verified files without running an engine. It has only the absolute v9 run directory inside this project's `artifacts/`, the ply, the frozen protocol hash, and byte hashes for the v9 plan, case manifest, request, raw response, result, and evaluation. It has no caller-supplied alternative or score. The CLI confines protocol, input, and output files to project artifacts and bounds metadata reads. V10 calls v9's full four-case verifier and preflight again, checks the selected packet, matched model identity, and checker source binding. A transport or identity failure has no eligible v10 input. A model abstention, rejected claim, or accepted claim without a model-named alternative produces a zero-engine-call abstention.

Only accepted `queen_escape` and `rook_coordination` claims can name a pair. V10 replays both legal roots on the pinned pre-move board. It then makes exactly one root-restricted paired search, maps observations by UCI rather than engine rank, and replays each saved PV. Missing or duplicate roots, invalid PVs, mismatched perspective, mate scores, and upper or lower bounds abstain. The receipt separates a comparison attempt from an actual engine `analyse` call: binary, spawn, or configuration failure counts one attempted comparison and zero `analyse` calls; a failed `analyse` counts one call and retains a bounded error. An unqualified centipawn pair yields `alternative - played`, with fixed wording that names White's or Black's score perspective and the one bounded search. “Unqualified” means the engine did not flag a bound, not that the position has a proven value.

The private receipt retains input/protocol/upstream/source hashes, the model ID and checker decision, attempt and `analyse`-call counts, engine settings and legal PVs when usable, a typed abstention or bounded comparison, and explicit `quality_evaluated:false` and `commentary_capability_gate_passed:false`. The CLI claims the create-only output path before evaluating; an occupied path consumes no search. It writes a small `reserved` record with evaluator, input, and protocol hashes and an explicit **unknown** search outcome if interrupted. A completed receipt replaces that record atomically from a same-directory temporary file. If an unexpected exception reaches the CLI, a source-bound `failed` record replaces it and likewise says the search outcome is unknown; it never reports zero calls without evidence. A process crash during the initial create/write window could still leave a zero-byte file, and a failed atomic replacement can leave a reserved record and a temporary file. Inspect that residue and native logs before any new attempt. Do not include this receipt or its PV in a v9 generator request. V9's complete nested request gate rejects future positions, PVs, alternative scores, and review labels.

## Practice controls and remaining gate

The retained ply-57 10,000-node `Rac1`/`Rb1` observation has an upper bound, so it is not an accepted ordering. The retained ply-93 `Rb8`/`Rc8` comparison favors the played move by 283 cp in one search, but v9's passed-pawn claim contains no model-named alternative, so v10 abstains there. These are observations from one known game, not blind Chess.com parity evidence. Passing offline software tests would establish the sidecar boundary only. The v8 and four-part v9 finite source reviews, an actual v9 capture, a separate finite v10 source review, and a fresh game-disjoint commentary assessment remain gates before quality claims or expansion to other games or sports.
