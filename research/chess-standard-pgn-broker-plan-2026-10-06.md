The new program should require a direct response at every fixed URL, reject redirects, credentials, content encoding changes and caller-provided URL/header fields, and use a single bounded deadline. Cap the page at 2 MiB, each plain-text index at 256 KiB, and the compressed PGN at exactly 1 MiB. The page must visibly declare CC0 and link to the exact standard archive. The list must contain that exact URL once; the checksum list must contain the exact filename with the currently published whole-archive digest `b2b22f4c62c198191e370337249dcdbe3cff3f88e74f7c08b707daf6e0018f4d`. A changed official digest should stop this frozen packet for a new source decision. The broker should accept only a valid Zstandard frame or bounded skippable-frame lead-in, as v1 already does.

For the archive request, require `206` with `Content-Range: bytes 0-1048575/<total greater than 1048576>`. If the server ignores Range and returns `200`, retain only the first 1 MiB, cancel the body, and require a trustworthy `Content-Length` greater than the retained prefix. Do not claim the full-file checksum verified the prefix. Retain `source-page.html`, `standard-list.txt`, `standard-sha256sums.txt`, `standard.pgn.zst.part`, and an immutable acquisition receipt with each file's bytes, SHA256, exact URL, status and response headers, the CC0 evidence, `synthetic:false`, and `fullArchive:false`. Check every retained byte, policy field and path before an existing target can be reused offline; never overwrite or silently refetch a conflicting target.
