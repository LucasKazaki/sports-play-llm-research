## What counts as an improvement

Every cycle must close one falsifiable question with an inspectable artifact: a reproduced and fixed software defect, a source-backed decision that changes a design choice, a rights/capability receipt that unlocks a specific experiment, or a paired experiment that passes a frozen acceptance rule. Plans, elapsed time, task counts, valid JSON, citations checked again without a change, and agreement between agents do not count as model improvement. Negative results and rejected candidates are useful only when they change the next decision.

Track three outcomes separately: project reliability, model-system performance, and learned-weight performance. A prompt, retrieval, validator, or user-interface fix belongs to the first two categories. Claim better weights only after actual training and a controlled evaluation. Never convert synthetic checks or the old three-example football test into a soccer performance claim.

## Next experiments, in order

Development tests, smoke experiments, inference preflights, training on eligible development inputs and error analysis are authorized project work now. They do not require completed publication review, independent test labels or a new operator execution grant. Record inputs, code/model identity, outcomes and failures so the result can be assessed honestly. The confirmatory evaluation and promotion requirements below govern scientific claims and untouched holdouts, not ordinary engineering iteration.

1. **Development query reliability.** Freeze a versioned, explicitly internal development case set before comparing prompts/guards. Include action omission, identity/jersey ambiguity, negation, temporal order, absent and repeated events, and long queries. Retain raw responses, exact model/endpoint, generation configuration, code/prompt hashes, latency and fallback/rejection reason. Compare the same saved response with and without validation to isolate the guard; compare fresh model calls separately. Score constraint preservation, unsupported filters, fallback coverage and latency. This is interface development, not visual accuracy.
2. **Permissioned retrieval pilot.** First confirm a usable export and processing rights. Ask a coach for concrete past retrieval tasks before showing the prototype. Build original-match-disjoint development data with independent relevance annotation; keep replays, halves, overlapping crops and alternate encodes in the same group. Compare literal/BM25 saved-report search, query-assisted retrieval and the grounded candidate under equal media and compute budgets. Freeze recall@k, nDCG, false-evidence rate and abstention/coverage definitions before scoring. Missing or failed outputs remain in the denominator.
3. **Visual/model-system hypothesis.** On a fresh, untouched test set, compare a direct video-VLM to the same backbone plus temporal/spatial tools. Include temporal-only and field-only ablations, shuffled/corrupted evidence, repeated inference at equal budget, null questions and close distractors. Human reviewers must label whether the corrupted input remains answerable. Primary outcome is joint answer-and-evidence correctness; report time/region errors and selective risk at prespecified coverage separately. Set practical effect sizes, power/precision targets, calibration rules and match-clustered uncertainty using development data, then freeze them before any test access.
4. **Learning only after evidence supports it.** Choose error-targeted training examples from development groups; separate prompt changes, retrieval changes and any fine-tuning. Keep a fixed baseline checkpoint and immutable candidate/prompt hashes. Promote only if the predeclared primary endpoint improves beyond the chosen practical threshold without unacceptable false-evidence, latency or coverage regression. Preserve the prior candidate for rollback. Test-set inspection cannot become training feedback; a changed hypothesis needs a new holdout.
5. **Coach utility, independently.** Use equal training, masked conditions and randomized/counterbalanced task order. Measure time to a correctly verified clip or answer, correction burden and confidence calibration, not just satisfaction or answer speed. Include unsuccessful tasks and uncertain cases. Sample size follows a development pilot and the planned unit of analysis; do not invent a powered sample size now.

## Doctoral standard and promotion

Before confirmatory held-out evaluation, close three additional prespecification gates. First, audit both local historical exposure and upstream model pretraining/benchmark contamination using available model cards, releases and source histories. When pretraining membership is unknown, label it unknown and use prospectively collected, authorized holdout games after the relevant model release where feasible; local match splitting alone cannot prove absence of contamination. Second, select one primary comparison, freeze the candidate-selection/stopping rule and limit development comparisons; define how secondary hypotheses and repeated checkpoint comparisons handle multiplicity. Never repeatedly peek at a nominally untouched test set to select the best candidate. Third, define zero-relevance/null-query scoring before evaluation: report false-positive retrieval/null rejection separately, mark nDCG undefined when no relevant item exists, and retain those queries in the appropriate overall denominators.
