## Runner state machine

Model the v7 runner's `freeze`, `capture`, `evaluate`, `verify` commands, but make schemas and filenames v9-specific. A single `freeze` invocation may freeze all four cases to a new parent directory, each with its own immutable manifest; alternately freeze one case at a time and add a separate four-case index. In either layout, write the four-case plan and denominator **before** the first POST. Reject an existing run directory. Never overwrite a manifest, packet, projection, request, response, result or evaluation.

1. **Freeze:** source-bound `build_packet`/`encode_packet` replays PGN and binds exact review JSON and page hashes. `v9.build_generator_input` returns the only model-visible user content. Require exactly nine outer keys: `schema`, `source_packet_sha256`, `source`, `fen`, `side_to_move`, `selected_move`, `transition`, `engine_observation`, `assertion_kinds`. Validate exact nested keys and scalar leaf types as v7 `build_request` does. Require canonical bytes, expected v9 schema, case binding, and allowed claim kinds. Reject PV, post-move FEN, future moves/features, annotations, Chess.com labels, solution/theme, alternative scores, evaluator witnesses or hidden nested objects. Construct the sole chat-completions request with v9 `PROMPT`, projection, model ID, sampling and seed; freeze exact request bytes and SHA-256. Manifest records packet/projection/prompt/request/route/attestation/source hashes, case identity, `requested:1`, `model_calls:0`, `automatic_retries:0`, `heldout_outcomes_scored:0`, `commentary_capability_gate_passed:false`.
2. **Preflight:** before any network call, re-read and hash every frozen artifact, source/review/page, implementation module and route evidence; regenerate packet projection and request bytes; confirm all match. Require explicit CLI pins for PGN/review/page/packet/model/endpoint/seed/request/manifest. No fallback route, prompt or model identity. Check no request sentinel or result already exists.
3. **Capture:** create `request.json` using exclusive create **before** issuing one POST to the exact loopback `/chat/completions` URL. Disable proxy and redirects; use the frozen 60-second timeout and zero retries. Preserve the raw HTTP response bytes on success and HTTP error, including malformed JSON, empty body and a bounded `MAX_RAW_BYTES+1` prefix for oversized bodies. Record latency, HTTP status, response hash/length, declared and observed model identities, transport exception type/message and attempt count. A transport failure may have no raw bytes; a request sentinel with no result is `interrupted` and consumes the attempt. Do not silently repeat after crash, timeout or ambiguous dispatch.
4. **Offline evaluation:** only for a captured, identity-matched HTTP response, extract exactly one plain assistant message with `finish_reason=stop`; reject tool/function calls, duplicate/nonfinite/deep JSON, empty or truncated content. Call `v9.evaluate` on the frozen packet and extracted bytes; retain the raw envelope and a checker receipt even when extraction fails, with an explicit error state. Do not let an extraction failure disappear from the four-case denominator. No model or engine call from evaluation, no resampling, no score delta or move ranking. `quality_evaluated:false` and gate false remain explicit.
5. **Verify/report:** read back exact hashes and status transitions. Verify a frozen case, spent interrupted case, HTTP/transport failure, captured case and evaluation consistently. Produce a four-row practice summary with counts for all four attempts; distinguish legal typed claim, abstention, format rejection and transport failure. A missing attempt stays visible as `not_run`, never as a success or excluded denominator. Do not present synthetic tests or four same-game answers as commentary competence.
