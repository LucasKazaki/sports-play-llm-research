# Comparing an arbitrary legal chess move

The Chess.com practice game asks why 20.Qc3 was worse than 20.Qe4. The earlier local paired review supplied one bounded engine comparison, but one game and one search cannot define a general move-quality rule. The new evaluator-only `scripts/chess_arbitrary_move_contrast_v1.py` accepts any selected legal move on a pinned standard-chess position. It searches without a root restriction to discover an alternative, then searches the selected move and that alternative together at 30,000 and 100,000 requested nodes. Scores are expressed from the mover's perspective, with mate and qualified bounds kept separate from exact centipawns.

An independent review caught an unsafe first version: it could combine final MultiPV ranks from different depths, or report a numeric loss when fake engine events said only one node had been searched. The revised source rejects unequal rank depths and requires each final score event to report at least four-fifths of its requested node budget. It also rejects Chess960 boards because the engine settings fix standard chess. Twenty-six fake-engine tests passed locally, and independent re-review passed this **bounded evaluator** scope. It retains no PV or post-move FEN in its output and has no generator interface.

These checks can produce a measured *pairwise observation* or an unresolved result. They do not establish why Stockfish prefers a move, whether a line is forced, or whether an explanation helps a learner. Source and engine binaries must be verified by the caller. A real Stockfish run on the pinned practice game and a separate no-forward model response remain next; neither has yet been established by these synthetic tests.

The separate `scripts/chess_arbitrary_move_practice_v1.py` verifies the exported Chess.com PGN, its 20.Qc3 pre-move board, each selected legal move, the pinned Stockfish binary, and the exact evaluator/helper source bytes before a launch. It reserves a create-only attempt, records failures as unresolved, and has an offline verifier that checks the saved score events and state transitions. Its synthetic preflight confirmed Qc3 and Qe4 from the same board; 49 combined fake-engine tests and independent source review passed. The local seal detects changed files but cannot authenticate an invented, coherently resealed engine transcript; the project-native execution receipt must bind an actual run and its output hashes.

The first real practice attempt (`r1`, native job `0d99692c-2fbd-4991-b2a5-34e58438853f`) passed 49 tests, then saved both Qc3 and Qe4 as unresolved `engine_exception`. A separate, finite diagnostic task `f1f61fe6-3da7-43c4-80d9-4792224e0da3` (job `cff0ca6d-f8cd-416a-8fb8-16f95fefb23d`) reproduced the exact `chess.engine.EngineError`: `UCI_Chess960` is automatically managed by python-chess and could not be set as an engine option. The same diagnostic succeeded in a 1,000-node search without that option. This located a launch-setting fault; it did not validate either chess comparison.

After removing that option, `r2` (job `ad2af891-5de7-4c03-b4be-be5f673bd442`) passed 49 tests and reached a real unrestricted 100,000-node discovery search from the game's move-20 position. It found Qe4 at -104 centipawns for White as an exact score and Qa2 at -275 as an **upper-bound** score. The evaluator stopped before its 30,000/100,000-node paired searches because the qualified score did not permit an exact numeric loss; both selected-move results remain `discovery_mate_or_qualified_score` and unresolved. This is useful engine evidence for the next comparison design, not a reason for Qc3's mistake label or a statement of Stockfish's intent.

The distinct `r3` run (job `455ff104-563a-41ad-8541-b8fc64c77e71`) passed 51 tests but exposed a stale practice verifier path: Qc3 saved `evaluator_failed_or_rejected`, and Qe4 also recorded a secondary `engine_cleanup_failed`. Both outputs remain unresolved despite the commands' zero exit codes and local file verification.

The repaired `r4` run (native task `6a5694f9-9297-4bf4-940e-99f408b2a905`, job `68195dc6-5454-4d7b-bbc6-36dcb1585c85`) passed 54 tests, ran Stockfish, and verified both saved result files. Its unrestricted discovery again recorded Qe4 at -104 exact and Qa2 at -275 upper-bound centipawns from White's perspective. For selected Qc3 against Qe4, the 30,000-node paired search recorded Qe4 -103 exact and Qc3 -411 upper bound, both at depth 12. The 100,000-node paired search recorded Qe4 -100 exact and Qc3 -453 upper bound, both at depth 14. The comparison still says `mate_or_qualified_score` and **unresolved**: those qualified Qc3 scores are not exact numeric losses. For selected Qe4 against Qa2, the low-budget paired search failed `incomparable_rank_depth`; the high-budget search did not run, so that comparison also remains unresolved. Independent analysis of what the bounds can support is under way. These are evaluator-only engine observations with zero model calls; they do not establish a game-logic explanation, Chess.com parity, or readiness to leave chess.
