# Ordinary completed-game development sample: source decision

**Checked:** 2026-10-06 14:10 UTC. **Status:** source and selection decision only. No PGN/archive bytes, game IDs, model output, or engine output were acquired for this memo. No holdout protocol is frozen.

## Decision

Use a capped prefix of the **September 2025 Lichess standard rated-game PGN** for one ordinary, completed-game *development smoke case*, then expand only through the existing 40-case development-cohort design. This source is independent of the Chess.com practice game and the project's earlier puzzle-prefix material. The first case tests the intake, legal replay, pre-move packet, and explanation path; it cannot measure capability or teaching quality. Keep the future holdout on a different month and freeze its protocol before opening that source.

The direct source is `https://database.lichess.org/standard/lichess_db_standard_rated_2025-09.pgn.zst`. Lichess's [database page](https://database.lichess.org/) lists it under **standard rated games**, says monthly files are not cumulative, and says Zstandard archives can be decompressed after a partial download. The official [standard download list](https://database.lichess.org/standard/list.txt) contains that exact URL. The [standard checksum list](https://database.lichess.org/standard/sha256sums.txt) currently gives `b2b22f4c62c198191e370337249dcdbe3cff3f88e74f7c08b707daf6e0018f4d` for the **entire** September archive. That digest cannot verify a 1 MiB prefix.

## Rights and access boundary

The [Lichess database page](https://database.lichess.org/) explicitly describes its database exports as CC0 and permits research, modification and redistribution. Its **broadcast** section separately states CC BY-SA 4.0; exclude broadcast, variant, puzzle, and evaluation exports from this route. The standard-game PGN can itself contain `%eval`, clock, result and other comments; those are source metadata, never generator input or unquestioned ground truth. Do not transfer Chess.com Game Review coaching prose or labels into this corpus. Retain source attribution and a rights snapshot even though the standard export's stated license is CC0. No account, paid API, or form is part of the proposed direct archive route, but the project's own scoped broker is still required for an actual fetch.

The existing Studio broker only admits a **Lichess puzzle CSV prefix**. A new exact-source alias, `studio-project-standard-pgn-acquire-v1`, is designed in `research/chess-standard-pgn-broker-plan-2026-10-06.md` but is not active evidence of acquisition. Have the Studio owner implement and review that separately versioned broker. Its one proposed request is compressed bytes `0–1,048,575` into a new create-only Sports target, with direct-response, byte-cap, content-range, official-page/list/checksum and immutable receipt checks. Retain URL, UTC fetch time, status, headers, bytes and SHA-256 for metadata and the actual prefix; declare `fullArchive:false`. A `206` response is not guaranteed by the database page; the reviewed broker must handle an ignored Range response under its stated cap or fail closed. Bind decompressed bytes to that compressed-prefix receipt, cap decompression, and discard/count the trailing incomplete PGN. Never claim the whole-file checksum certifies the prefix.

## One-case selection, fixed before seeing games

1. Parse only complete records from the retained prefix. Require an exact `Site` URL with an eight-character Lichess game ID, standard initial position, standard variant, parseable result, at least 16 plies, initial time control of at least 300 seconds, and error-free legal mainline replay with a pinned `python-chess` version. Count every rejection reason. A result tag declares completion; it need not imply checkmate.
2. Before ranking, query a **sealed-safe, count-only exclusion oracle** covering the frozen v1 games, historical eight cases, v2 train/dev/sealed games, every project prompt/practice/evaluation game, and the Chess.com practice game. Exclude matching namespaced IDs, identical normalized UCI trajectories under another ID, and any canonical pre-move position already used or protected, even if the played move differs. The oracle must not reveal sealed case payloads. If it is unavailable, select nothing.
3. Use the already specified development seed `standard-dev1`: sort complete eligible games by `SHA256("standard-dev1|lichess:<id>")`, tie-break by ID, and inspect at most the first **400**. For each game consider played plies **16–160**. A quiet-shaped candidate is a played move that is no capture, check or promotion while its mover is not in check. Rank candidates by `SHA256("standard-dev1|lichess:<id>|<ply>")`, tie-break by ID and ply, and take the first candidate surviving position exclusion as the one-case smoke sample. If none exists inside the cap, report the shortfall. Do not hand-pick a more interesting position, change the source cap, or top up after inspection. The later full stress-cohort selector retains its separate 200-position and eight-per-stratum caps.
4. Retain the source game ID, canonical pre-move FEN hash, selected UCI/SAN, full-game trajectory hash, selection rank, all exclusions and denominator counts in a create-only development receipt. Keep the raw PGN local; the existing GitHub mirror should receive only rights/context notes and software, not this source file or player headers. The generator sees only the no-forward allowlist. Later moves, comments, result, engine continuations, alternative scores and selection labels remain evaluator-only.

This is deliberately one case from one game. It is game-disjoint from the Chess.com practice game by source and must also pass explicit protected-overlap checks. It is **development**, so no observation from it can become a blind heldout result. A separate fresh month, exclusion registry, sampling/engine/model pins, reviewer commitments and prospective thresholds are still needed before the [holdout protocol](chess-game-disjoint-heldout-protocol-2026-10-06.md) can be frozen. General-model pretraining overlap cannot be proven absent.
