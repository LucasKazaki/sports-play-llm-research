## Function-level findings

1. **`prompt_for` (lines 20–24): no answer-bearing model inputs found.** It reads only the current FEN and emits the declared native `P: ` plus padded FEN plus `M:` prefix. Candidate moves, teacher scores, PVs, themes, annotations and target fields are not read. The current FEN is after the source opponent setup move and before the teacher action; it is not a teacher-result board.
2. **`make_example` (35–51), imported `collate` and `completion_nll`: joint boundary and loss accounting are consistent.** The complete prefix/space/UCI/EOS string is tokenized jointly, crossing boundary tokens are rejected, and separately encoded inference-prefix IDs must match exactly. Prefix targets and right-padding targets are `-100`; real EOS remains supervised. The native tokenizer probe passed all 8,192 train and 128 development rows, with maximum sequence length 93 (native context limit 1,024). Every supervised suffix decodes to the intended UCI move and EOS. `completion_nll` weights each batch loss by the count of shifted nonmasked target tokens, rather than by batch size. These are tokenization/accounting checks, not model predictions.
3. **`parse_action` (27–32) and `evaluate` (128–173): no late rescue found.** Only the first whitespace-delimited generated action is considered after the explicitly allowed leading `M:` marker. A malformed first token, a `B:`-only answer or an illegal parsed move cannot be rescued by later valid text or legal masking. Generated token IDs and raw trailing completion text are retained. The same parser and generation budget apply to base and trained conditions, as the frozen protocol requires.
4. **`evaluate`: planned failure denominator is preserved for the declared backend failures.** Shape, encoding, generation and decode exceptions account for the whole affected batch and stop later calls; all subsequent planned rows become explicit `not_run_after_backend_failure` records. Parse failures and syntactically valid illegal moves remain in the raw denominator. Independent tests cover exception and malformed-shape paths, one backend call, complete row accounting and the distinction between parsed-illegal and unparsed outputs. `backend_failure_count` counts affected/not-run rows, not the number of failed backend calls.
5. **`acquire` (54–90) plus imported `select_rows`/`historical_exclusions`: the source exclusion path matches the protocol.** Historical game IDs and replay roles are excluded. Every v1/v2/v3 selected game and current board is added, then prior puzzle IDs reconstruct their original source-before role from the exact retained prefix. New rows are accepted only when their game and both before/after board keys are unused, and both roles are reserved upon acceptance. Source hash and prior manifest hashes are retained; split assignment is the declared game-hash rule. The separate assigned data reviewer owns the independent source replay and actual overlap verdict; this review does not substitute for that audit.
6. **`label` (93–125), imported `classifier.label_batch`, and `validate_training_bindings` (180–195): pre-call evidence and label identities are coherent.** Actual 8,576 row bindings passed: exact protocol/dataset hashes, teacher settings and engine identity, split sizes, row ID/game/FEN equality, and legal teacher actions. The pre-teacher snapshot hashes match all current executed source files, and the labels bind that pre-call receipt. The imported teacher uses one thread per worker, declared hash size/node budget, hash clear per position and the actual completed legal UCI bestmove. Score observations preserve each individual score event's own bound flags and are not generator inputs or training targets.
7. **`train` (198–310) and `selection_key`: selection precedes holdout scoring.** The reviewed path evaluates base/development first, trains the fixed 2,048 updates, checks only the declared development checkpoints and selects by raw matches, raw legality, then earliest step including base. The selection file and selected weight hash are saved before either holdout model evaluation. Only base and the selected checkpoint enter the holdout branch. Development NLL is diagnostic and does not replace the declared selection criterion.
8. **`train` evidence retention: source, tokenizer/model and checkpoint identities are inspectable.** Executed source/protocol snapshots, actual base metadata hashes, base weights and label hash are captured before LM loading. Checkpoints save both model and tokenizer. The final receipt binds selected weights, selection file, dataset, labels and optimizer log. Local-only built-in Transformers loading is used; no remote model Python is requested. The reviewed source matches the pre-teacher source snapshot, and there were no source edits by this reviewer.
